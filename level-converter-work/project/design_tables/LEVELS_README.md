# Excel 关卡制作规范

`xlsx/levels.xlsx` 是关卡布局的策划编辑源。工作簿包含 `填写规范`、`图例` 和任意数量的 `map_` 地图子表。

## 基础规则

- 每个逻辑格固定对应 Godot 世界中的 `32 × 32 px`。
- 地图子表名称必须以 `map_` 开头。
- 每张地图可以配置不同的格子宽度和高度，默认 `48 × 32` 格。
- Excel 从左上角开始按列、行编号；Godot 世界原点位于地图中心。
- 地图有效范围内每格都必须包含基础地形代码，不能留空。
- 最外圈必须使用 `X` 闭合，防止玩家离开地图范围。
- 同一单元格可用英文分号组合地形和对象，例如 `R;C:1`。

## 地图子表固定位置

| 单元格 | 含义 |
| --- | --- |
| `B3` | `map_id`，稳定的地图 ID |
| `D3` | 地图显示名称 |
| `F3` | 地图宽度，单位为格 |
| `H3` | 地图高度，单位为格 |
| `J3` | 逻辑格尺寸，当前固定为 32 |
| `L3` | 默认地形代码 |
| `B9` | 地图网格左上角 |

默认地图为 `48 × 32` 格，因此有效网格是 `B9:AW40`。转换工具只检查由宽度和高度定义的范围。

## 首版代码

### 基础地形

- `G`：草地，可通行。
- `R`：泥土道路，可通行。
- `W`：河流，不可通行。
- `BR`：桥梁，可通行。
- `X`：地图外区域/外边界，不可通行。

### 环境物件

- `RB`：自动连接木质栅栏，不可通行。
- `T`：树木，不可通行。
- `BU`：灌木，可通行。
- `GT`：草丛装饰，可通行。
- `H1`：西侧房屋，不可通行。
- `H2`：东侧房屋，不可通行。

### 玩法对象

- `P:<方向>`：玩家出生点，方向为 `U/D/L/R`，省略时默认为 `D`。
- `C:<loot_group_id>`：宝箱。
- `N:<enemy_id>:<方向>:<巡逻半径格数>:<速度>`：普通怪。
- `E:<enemy_id>:<方向>:<巡逻半径格数>:<速度>`：精英怪。
- `BO:<enemy_id>:<方向>:<巡逻半径格数>:<速度>`：Boss。

敌人可选方向：

- `LR`：初始向右，水平巡逻。
- `RL`：初始向左，水平巡逻。
- `UD`：初始向下，垂直巡逻。
- `DU`：初始向上，垂直巡逻。
- `NONE`：不巡逻。

省略敌人可选参数时，默认使用 `LR`、`2.5` 格和 `70 px/s`。

## 组合代码示例

```text
G;P:R
R;C:1
G;N:1:LR:3:72
G;E:1000:DU:2:56
G;BO:2000:NONE:0:0
G;RB
```

所有分隔符必须使用英文半角冒号 `:` 和英文半角分号 `;`。

## 多格素材

大于一格的素材必须完整绘制实际占用范围。左上角主格在素材代码末尾添加 `@`，其余格填写相同素材代码。

`2 × 2` 示例：

```text
G;H1@   G;H1
G;H1    G;H1
```

参数化对象示例：

```text
G;BO:1000:RL:2:56@   G;BO:1000
G;BO:1000             G;BO:1000
```

转换工具会依据图例中的最终占格宽高检查完整性、越界和重叠。少填、多填或形状错误都会返回具体单元格。

## 素材尺寸和缩放

图例中记录：

- 原始宽度和高度。
- `display_scale` 显示缩放倍数。
- 公式计算的当前显示宽度和高度。
- 自动占格宽高。
- 可选的占格覆盖宽高。
- 最终占格宽高。

地形始终铺满 `32 × 32 px` 逻辑格。独立物件按显示尺寸除以 32 后向上取整。素材存在透明留白时，可以填写占格覆盖值。

## 刷新规则

- 宝箱和敌人的状态只在本次地图停留期间保留。
- 本次停留期间，搜空宝箱和死亡敌人不会刷新。
- 离开并重新进入地图后，所有宝箱和敌人恢复初始状态。
- 因此对象不要求策划填写持久实例 ID，运行时身份由地图 ID 和坐标生成。

## 生成场景

每张地图生成两个场景：

```text
scenes/maps/generated/map_<map_id>_generated.tscn
scenes/maps/map_<map_id>.tscn
```

- `generated` 场景由工具覆盖更新。
- 外层场景只在首次创建，实例化生成场景并保留 `ManualOverrides` 节点。
- 手工扩展必须放在 `ManualOverrides`，不要修改生成场景实例内部节点。

生成场景按 `Terrain`、`Environment`、`Gameplay` 和 `Collisions` 分组。大面积地形使用批量实例渲染，静态物件使用现有像素素材，宝箱和敌人使用独立场景实例。

敌人、Boss、玩家和宝箱只占一个逻辑格，该格代表出生或放置点，不需要填写多格延伸代码。旧地图中已经使用 `@` 绘制的敌人多格块仍兼容，并会合并为一个敌人实例。房屋、树木、灌木等静态物件继续严格遵守多格和 `@` 规则。

## 默认入口

每个 `map_` 子表在第 4 行配置：

| 单元格 | 内容 |
| --- | --- |
| `K4` | 固定填写 `默认入口` |
| `L4` | 填写 `是` 或 `否` |

所有地图中必须且只能有一张填写 `是`。转换工具会保持 `world.tscn` 为项目主场景，并将其中的地图实例切换为该外层地图场景。

## 运行转换

关闭 Excel 后双击：

```text
design_tables/convert_levels.bat
```

工具先校验所有地图，再统一写入生成结果。任意地图校验失败时，不会修改已有生成场景、默认地图或增量清单；错误信息会包含工作表和 Excel 单元格地址。

## 增量规则

- 工具保存每张地图的标准化哈希和上一版单元格快照。
- 未变化的 `map_` 子表跳过。
- 变化地图会列出修改、新增和删除的格子，然后完整重建该地图的 generated 场景。
- 图例资源变化时，只重建使用该资源代码的地图。
- 外层包装场景和 `ManualOverrides` 不会被重写。

## 基础校验

- 地图 ID 不得重复。
- 地图尺寸必须为正整数，`cell_size` 必须为 32。
- 有效范围内不得出现空白格或未知代码。
- 外圈必须全部为 `X`。
- 玩家出生点必须且只能有一个。
- 宝箱引用的 `loot_group_id` 必须存在。
- 敌人引用的 `enemy_id` 必须存在，`N/E/BO` 必须与敌人类型匹配。
- 多格素材必须尺寸正确、不可越界、不可互相重叠。
- 不可通行对象不能覆盖玩家出生点。
